# ESP32-2432S024C — экран, тач, SD и Vuesp

**Коротко:** `vuesp.lcd-2432S024C` — прошивка Vuesp **5.0.0** для платы **Sunton/DIYmalls ESP32-2432S024C**. Это ESP32 с экраном 2.4" 240×320 (ILI9341), ёмкостным тачем CST820, microSD, RGB-светодиодом, динамиком, LDR и входом батареи. Web UI — **5.0.0**.

## Что это за устройство

Плата собрана вокруг ESP32:

- 2.4" TFT 240×320, драйвер **ILI9341**;
- ёмкостный тач **CST820** по I2C;
- microSD на отдельном SPI;
- RGB-светодиод (общий анод, active-low);
- динамик через DAC GPIO26 и усилитель FM8002A;
- LDR на GPIO34 и вход батареи на GPIO35;
- USB-C с CH340, кнопки BOOT/RESET.

В первой версии локальный экран показывает статусы и диагностику, а веб-интерфейс даёт страницы управления экраном/тачем/SD и конструктор дополнительных экранов с картинками и живыми данными. OTA и стандартные возможности Vuesp сохранены.

## Распиновка

Плата — **ESP32-2432S024C** (C-версия, ёмкостный CST820). Таблицы для 2.8″ `ESP32-2432S028R` с XPT2046 сюда не подходят: там другой тач и подсветка на GPIO21.

### Разъёмы на плате

На шелкографии подписаны `P1`, `P3`, `CN1` и `P4`. Порядок контактов на JST зависит от ориентации разъёма — проверяйте по шелкографии и мультиметром.

| Разъём | Состав | Назначение |
| --- | --- | --- |
| **P1** (4-pin) | `VIN` (5V), `IO1/TX`, `IO3/RX`, `GND` | UART0 через CH340 и питание |
| **P3** (4-pin) | `GND`, `IO35`, `IO22`, `IO21` | внешние GPIO, датчики |
| **CN1** (4-pin) | `GND`, `3V3`, `IO22`, `IO21` | внешние GPIO / I2C |
| **P4** (2-pin) | динамик | выход FM8002A, не GPIO |

`IO21` и `IO22` — общие цепи: один и тот же вывод выведен и на P3, и на CN1.

### Внутренние цепи

| Сигнал | GPIO | Примечание |
| --- | --- | --- |
| TFT MOSI / MISO / SCLK / CS | 13 / 12 / 14 / 15 | HSPI, заняты дисплеем |
| TFT DC / BL | 2 / 27 | подсветка через AO3402 |
| Touch SDA / SCL / RST / INT | 33 / 32 / 25 / 21 | CST820, адрес `0x15` |
| SD CS / MOSI / MISO / SCK | 5 / 23 / 19 / 18 | VSPI |
| RGB R / G / B | 4 / 16 / 17 | active-low, 255 = off |
| Speaker | 26 | DAC, только через усилитель |
| LDR | 34 | ADC, input-only |
| Battery | 35 | ADC, input-only, выведен на P3 |
| BOOT | 0 | strapping, кнопка BOOT |

Дисплей и SD разнесены по разным SPI: TFT_eSPI использует HSPI (`USE_HSPI_PORT`), SD — VSPI.

### GPIO-интерфейс

Страница **`/device/gpio/`** показывает не все выводы ESP32, а список из `ports[]` в `src/gpio/gpio.cpp`. Автоматического перебора пинов нет.

Сейчас в интерфейсе **7 карточек**: `0`, `4`, `16`, `17`, `22`, `34`, `35`.

| Внешний GPIO | Где доступен | В интерфейсе |
| ---: | --- | --- |
| 0 | кнопка BOOT | да |
| 1 | P1 `TX` / UART0 | нет — занят CH340 |
| 3 | P1 `RX` / UART0 | нет — занят CH340 |
| 21 | P3 и CN1, INT тача | нет — занят CST820 |
| 22 | P3 и CN1 | да |
| 35 | P3, input-only / батарея | да |

Итого из внешних выводов на странице есть **0, 22, 35**. `1` и `3` не показываются, чтобы не сломать USB-serial; `21` не показывается, потому что используется как INT тача.

Пины `4`, `16`, `17`, `34` тоже есть в интерфейсе, хотя это внутренние цепи RGB и LDR. `26` и `27` управляются отдельными протоколами (`KEY_SPEAKER`, `KEY_DISPLAY`), а не как сырые GPIO.

### Варианты платы

- **C** (эта плата): CST820, SDA33/SCL32/RST25/INT21, подсветка GPIO27.
- **R**: XPT2046, другие пины тача (25/32/33/36/39) и подсветка GPIO21; прошивка и таблицы этой платы для R-версии не подходят.

## Локальный экран

Диагностический экран обновляется раз в секунду и показывает:

- Wi-Fi: SSID, IP, RSSI;
- uptime, свободный и минимальный heap;
- тач: состояние, последние координаты, raw-координаты, число нажатий;
- драйвер (`ILI9341`/`ST7789`), разрешение;
- SD: объём и занятое место.

Подсветка управляется ШИМ на GPIO27. Яркость 0 выключает подсветку.

Экранов может быть несколько: свайп влево/вправо перелистывает их по кругу, внизу рисуются точки-индикаторы. Диагностика — экран 0, она всегда остаётся доступной.

## Веб-страница Display и dashboard

Плитки dashboard: **brightness** (0–255), **backlight** (вкл/выкл), **orientation** (альбомная/перевёрнутая), **touch** (состояние/координаты) и **SD** (занято/всего).

Страница **`/device/display/`** объединяет управление экранами:

- список экранов, загрузка картинок, живые метки, свайп.

Яркость, подсветка и ориентация управляются плитками dashboard; настройки хранятся в `ConfigStore` (`/tmp/config.bin`). Состояние тача и SD-карты остаётся доступно через GPIO/dashboard и страницу `/device/storage/`.

Протокол: `KEY_DISPLAY` (15), структура `Display` (44 байта). Команды: `CMD_GET`, `CMD_SET`.

## Экраны, картинки и скрипты

Раздел **Screens** на странице `/device/display/` позволяет собрать до 8 экранов:

- **Status** — встроенная диагностика;
- **Image** — JPEG 320×240, загруженный через браузер;
- **Data** — цветной фон и до 8 текстовых меток.

### Загрузка картинки

В диалоге загрузки картинка сразу показывается в кадре 320×240:

- перетаскивание мышью/пальцем, колесо или ползунок масштаба 10–400%;
- `Fit` / `Fill` / `Reset`, поворот на 90°;
- цвет фона (он же фон экрана);
- имя файла и выбор хранилища: **LittleFS** или **SD**.

В браузере картинка рендерится в canvas 320×240 и уходит на устройство уже готовым JPEG (quality 0.85), поэтому превью совпадает с экраном. На устройстве кадр декодируется `TJpg_Decoder` блоками и выводится через `pushImage`; при rotation 3 TFT_eSPI сам разворачивает вывод. Если карта SD вынута, экран с SD-картинкой показывает `SD missing`.

### Метки и переменные

Текст метки может содержать подстановки:

- `{u0}` — `$u0` (uint);
- `{i0}` — `$i0` (int);
- `{f0}` / `{f0:1}` — float с 2 или 1 знаком после запятой (0–3);
- `{s0}` — строка `$s0`;
- `{p34}` — сырое значение порта GPIO34 (ADC).

Метки перерисовываются 4 раза в секунду и только при изменении текста. Экранные шрифты TFT_eSPI — ASCII, поэтому кириллица в метке заменяется на `?`; веб-интерфейс предупреждает об этом.

Пример скрипта для экрана Data:

```text
while:1;
  $f0=$p35*3.3/4095*2;
  $u0=$p34;
  wait(1s);
end;
```

### Функции ScriptRunner

| Функция | Назначение |
| --- | --- |
| `sshow(n)` | показать экран `n` (с нуля) |
| `snext()` / `sprev()` | следующий / предыдущий экран |
| `sindex()` | вернуть индекс активного экрана |
| `sval(slot, value)` | задать метке текст или число вручную |
| `sreset(slot)` | вернуть метке шаблон |
| `srefresh()` | перерисовать экран |

События: `screen` (`$e0` — новый индекс), `swipe` (`$e0` — +1/−1, `$e1` — индекс), `touch` (`$e0`/`$e1` — x/y, `$e2` — индекс). Пример:

```text
on('btn_c');
  snext();
end;
```

### Примеры скриптов

Стартовый набор лежит в `vue/public/scripts.txt` и после `build-web` попадает на устройство как `/www/scripts.txt`:

| ID | Имя | Что делает |
| ---: | --- | --- |
| 0 | `boot` | пишет приветствие в лог, экраны не меняет |
| 1 | `screen_next` | показывает экран 1 и логирует индекс |
| 2 | `screen_tour` | по очереди показывает экраны 0–2 по 2 секунды |
| 3 | `touch_log` | логирует `touch`: x, y и индекс экрана |
| 4 | `swipe_log` | логирует `swipe`: направление и индекс |
| 5 | `screen_log` | логирует `screen` при смене экрана |
| 6 | `data_counter` | пишет числа 0–99 в метку 0 через `sval()` |

`data_counter` рассчитан на экран типа **Data** с меткой `slot=0`. События `touch`, `swipe` и `screen` регистрируются только после ручного запуска соответствующего скрипта.

Подсказки для редактора: `sshow`, `snext`, `sprev`, `sindex`, `sval`, `sreset`, `srefresh` и события `screen/swipe/touch` лежат в `vue/json/suggestions.json`. Глобальные `fade()`, `udp()` и `http()` приходят из `vuesp-components`.

### Конфиг и API

Раскладка хранится в **`/screens.cfg`** (текст, до 6 КБ), активный экран и режим свайпа — в `ConfigStore`. Картинки лежат в `/images/` на LittleFS или SD. Формат строк:

```text
V1
screen=0|Status|status
screen=1|Photo|image|lfs|/images/photo.jpg|#000000
screen=2|Data|data|#000000
label=2|0|8|16|304|32|4|#00FF88|left|Temp: {f0} C
```

HTTP API:

| Метод | URI | Назначение |
| --- | --- | --- |
| GET | `/screens` | JSON со списком экранов, активным и свободным местом |
| POST | `/screens` | multipart `config` с текстом `screens.cfg` |
| GET | `/screens/image?location=lfs&file=/images/x.jpg` | отдать JPEG |
| POST | `/screens/image?name=x&location=lfs` | multipart `file`, лимит 300 КБ |
| DELETE | `/screens/image?location=lfs&file=/images/x.jpg` | удалить файл |
| POST | `/screens/activate?index=1` | показать экран |
| POST | `/screens/state?swipe=0` | включить/выключить свайп |
| POST | `/screens/reset` | вернуть один статусный экран |
| GET | `/screens/probe?x=0&y=0&w=32&h=32` | диагностика: сколько пикселей отличается от чёрного |

Протокол: `KEY_SCREEN` (17), структура `Screen` (44 байта). Команды: `CMD_GET`, `CMD_SET` (активный экран и свайп), `CMD_CHANGE` (следующий), `CMD_RESTORE`. На dashboard есть плитка **screen** с именем активного экрана и переходом к следующему.

## Тач CST820

- I2C: SDA33, SCL32, 400 кГц, адрес `0x15`;
- сброс: RST25, импульс INT21;
- после сброса регистр `0xFE = 0xFF` отключает автоматический сон;
- координаты читаются из регистров `0x02`/`0x03`;
- локальный экран использует альбомную ориентацию; сырые координаты показываются рядом с преобразованными.

## SD-карта и файловый менеджер

SD монтируется на VSPI:

- CS5, SCK18, MISO19, MOSI23;
- при отсутствии карты попытки повторяются раз в 30 секунд;
- в UI и на экране показываются объём и занятое место.

На странице **`/device/storage/`** два блока: **File Browser** для LittleFS и **SD card** для карты. SD-блок умеет:

- входить в папки и возвращаться по хлебным крошкам;
- показывать файлы и их размер;
- загружать файлы и создавать недостающие папки;
- скачивать файлы;
- удалять файлы и пустые папки;
- перетаскивать файлы и папки между LittleFS и SD (копирование, папки — рекурсивно).

HTTP API SD: `GET /sd/list?path=/`, `GET /sd?file=/path` (скачать), `POST /sd` (multipart `file[i]`), `DELETE /sd?file=/path`, `POST /sd?format=true` (полное форматирование FAT через `f_mkfs`). Формат в UI требует подтверждения и стирает все данные карты. Длинные имена файлов обрезаются многоточием, полное имя показывается во всплывающей подсказке. При перетаскивании файла или папки на другой блок прошивка копирует его рекурсивно; существующий файл перезаписывается, оба списка перезагружаются.

## RGB, динамик, LDR, батарея и кнопка

- **RGB** R4/G16/B17 — три PWM-порта, active-low (255 = выключено). На dashboard есть карточка **palette** на базе `CardBase`: палитра цветов, свой color picker, включение/выключение. Текущий цвет хранится в `Device.rgb` как `#RRGGBB` или пустая строка; карточка отправляет один `KEY_DEVICE` с `CMD_SET`, прошивка атомарно обновляет все три канала. Код: `../vuesp-components/src/components/dashboard/cards/CardPalette.vue`; после правок библиотеки нужен `npm run build` в `vuesp-components`.
- **Динамик** GPIO26 — отдельный протокол `KEY_SPEAKER` (16), короткий beep через `tone()`. На dashboard есть плитка **beep**; частота/длительность по умолчанию 1000 Гц / 150 мс. Усилитель FM8002A имеет фиксированный коэффициент, поэтому `volume` сохраняется, но не меняет громкость.
- **LDR** GPIO34 — ADC-порт; на dashboard плитка `light` показывает процент.
- **Батарея** GPIO35 — ADC-порт; плитка `battery` показывает напряжение из расчёта делителя 1:2 (при другой схеме нужно калибровать).
- **Кнопка BOOT** GPIO0 — вход с прерыванием; плитка `button` показывает `PRESSED`/`RELEASED`, события `btn_c`/`btn_l` доступны ScriptRunner. Не удерживайте кнопку при включении — это strapping-пин.
- Все они доступны на странице GPIO и через ScriptRunner/порты Vuesp. Свободный GPIO22 выведен на P3; внешние I2C/OneWire-датчики штатно не заведены.

## Плитки dashboard

- **brightness / backlight / orientation / touch / SD** — экран;
- **light / battery / button** — LDR, батарея, BOOT;
- **beep** — короткий звук динамика;
- **palette** — выбор цвета RGB-светодиода: палитра, свой цвет, выключение.

## Сборка и прошивка

```bash
cd vue
npm ci
npm run protocol
npm run build-web

cd ..
~/.platformio/penv/bin/pio run -e esp32
~/.platformio/penv/bin/pio run -e esp32 -t buildfs
```

`vuesp-components` подключён к `vue` как `file:../../../vuesp-components`. После правок в его `src` соберите библиотеку (`cd ../../vuesp-components && npm run build`), иначе устройство продолжит использовать старый `dist`.

Заливка:

```bash
~/.platformio/penv/bin/pio run -e esp32 -t upload
~/.platformio/penv/bin/pio run -e esp32 -t uploadfs
```

OTA: обновление прошивки через `/update`, веб-файлы — через `/fs` или полный `littlefs.bin`. Раздел `default.csv` оставляет два OTA-слота по 1.25 МБ.

> `pio run -t uploadfs` пересоздаёт LittleFS целиком: пропадут `/tmp/config.bin` (Wi-Fi, яркость, порты), `/screens.cfg` и загруженные картинки. Для обновления только веб-интерфейса загружайте файлы через `POST /fs`.

Если панель не ILI9341, а ST7789:

```bash
~/.platformio/penv/bin/pio run -e esp32-st7789 -t upload
```

## Ограничения

- Нет PSRAM; локальный UI без LVGL, только TFT_eSPI.
- Ориентация локального экрана — альбомная (1/3).
- SD — отдельный файловый менеджер; формат SD стирает карту полностью и требует подтверждения.
- LDR/батарея без калибровки.
- RGB active-low; не путать 0 и 255.
- Драйвер экрана определяется при сборке; ILI9341 и ST7789 — разные окружения.
